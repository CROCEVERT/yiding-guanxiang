# 易定观象｜内容自查失效复盘

## 这次到底错在哪里

用户此前明确要求：

- 现代读者必须先读懂经文本身在说什么；
- 不要把所有爻做成同一种空泛建议；
- 文字必须大白、自然、能读通；
- 要自查并把问题写入复盘。

但本项目把每爻的 `meaning` 字段标作“**大白话**”，实际却经常把四件不同的事混在同一段里：

1. 原文的直接意思；
2. 古代身份或制度背景；
3. 对原文的解释性推论；
4. 面向当代问题的行动建议。

天山遁九三“系遯，有疾厉，畜臣妾吉”就是直接证据。旧文没有先解释“系遯”“有疾厉”“畜”“臣妾”“吉”各在说什么，先跳到了“私情、旧关系、碎事、重大方向”等现代概括。读者看完仍不知道经文意思，却被告知这叫“大白话”。

这是内容设计错误，也是自查失效；不是用户表达不清。

## 我做错的检查

此前“全量扫描”检查了以下机械指标：

- 64 卦、384 爻是否有内容；
- 是否为 `reviewed` 状态；
- 是否为空、过短、完全重复；
- 是否有内部研究标记；
- 页面是否有重复模块。

这些检查有价值，但**不能证明文字被读懂**。我错误地把“有一段不同于别爻的文字”当成“已经把这爻解释清楚”。

尤其漏掉了四项最基本的内容验收：

1. **标题—内容一致性**：既然叫“大白话”，第一句必须就是原文的直接现代译文。
2. **古词覆盖**：读者会卡住的词必须单独解释，不能藏在一整段推论里。
3. **层级分离**：直译、背景、解释、行动提示不得混写。
4. **陌生读者试读**：不能由写作者自己凭感觉判定“能读懂”；必须按用户视角逐条核对。

## 根因

### 1. 用数据状态代替内容质量

`reviewed` 原本只说明“有一份发布用文本，且六爻齐全”，却被我错误说成“已审核、可交付”。它没有证明逐句翻译准确、文字通顺或符合用户的阅读目标。

### 2. 把“避免模板化”误解为“加入更多现代解释”

为避免重复，我让每爻加入不同的现代场景、行动和误读边界；结果反而把最需要先完成的直译淹没了。不同不等于清楚，长也不等于解释。

### 3. 没有把知识库材料落实为“逐句翻译依据”

虽然读取了经典文本与课程转写，但没有先把它们沉淀为“原句—关键词—直接译文—背景说明”的工作表，就直接写成面向用户的综合段落。这使知识材料只影响了主题方向，没有保证每句经文被说清。

### 4. 自查结论越界

“64/64、384/384 均为 `reviewed`”只能说明程序没有缺条和回退，不能说明内容质量通过。我把数据完整性结论写成了近似“全量内容通过”的结论，造成了错误预期。

### 5. 没有对最显眼的失败信号做反向检查

“大白话”三个字本身就是一个强承诺。页面一旦出现它，就必须追问：“一个完全不懂原文的人，能否只读这段就复述原意？”我没有做这个检查，是本次最直接、最低级的遗漏。

## 对用户造成的后果

- 用户花时间验收后，仍需亲自指出本应由我发现的明显问题。
- 页面把混合解释包装为“大白话”，会误导用户以为自己读不懂是个人问题。
- 之前的“扫描通过”结论不够准确，削弱了复盘记录和验收的可信度。
- 如果继续按旧方式扩写，会把同类问题放大到 64 卦、384 爻，增加后续返工成本。

## 立即纠正

1. 已删除界面“大白话”标签，改为“这句话的意思”。这只是修正命名，不代表旧文本已经合格。
2. 已停止把现有 64 卦、384 爻称为“内容验收通过”。现有的 64/384 只能称作“**数据覆盖完整**”。
3. 已单独建立《天山遁逐句白话试稿 v1》，不写入程序。它把卦辞、象曰、六爻拆成“这句话的意思／词语说明／可以怎么读”。
4. 在用户确认天山遁试稿前，不再批量覆盖其他 63 卦，也不再报告“内容全绿”。

## 后续必须执行的内容闸门

任何一卦、一爻要进入程序，必须同时满足以下条件：

### A. 直译闸门

- 第一段只说明原文直接说什么，不放行动建议。
- 读者不看原文，也能复述句子的基本人物、动作、条件和结果。
- “吉、凶、利、贞、悔、吝、厉、无咎”等有当条的语义说明，不偷换成现实保证或恐吓。

### B. 词语闸门

- 古代官职、身份、器物、制度、通假字和易误读词必须单列解释。
- 古代性别、等级、战争、刑罚和祭祀语境必须明确说明“不能直接当成现代规范”。

### C. 层级闸门

- 固定顺序：**原文 → 这句话的意思 → 词语说明（如需） → 可以怎么读（如需）**。
- “可以怎么读”必须能回指前面的原文和词义；不能以“资源、关系、边界、行动”等泛词替代翻译。
- 现实行动若保留，必须是最后一层，且不能冒充原文原意。

### D. 可读性闸门

每条必须用以下问题自问，并由用户抽样确认：

1. 第一次读的人知道这句在发生什么吗？
2. 他能指出自己不懂的古词在哪里，并在词语说明里找到答案吗？
3. 删除“可以怎么读”后，前两层仍是一段完整的翻译吗？
4. 把卦名、爻名遮住后，这段是否仍只适用于这句经文，而不是任何卦都能套？

### E. 发布闸门

- “文本齐全”与“用户验收通过”分开标记，不得混用 `reviewed` 一词。
- 用户至少通过代表性样本（不同古代语境、不同难度、静卦和动爻）确认结构后，才允许批量迁移。
- 批量迁移后必须做第二轮随机抽读，不能只跑代码测试。

## 新的状态定义

| 状态 | 含义 | 能否对用户说“已完成” |
|---|---|---|
| 数据覆盖完整 | 64 卦、384 爻都有字段 | 不能 |
| 直译待验收 | 已有“直译—词语—阅读”草稿 | 不能 |
| 用户抽样通过 | 用户确认代表性样本结构可读 | 只能说“结构通过” |
| 全量语言验收通过 | 64 卦、384 爻按同一标准重写并抽检 | 才可以 |

## 防止再次发生的执行承诺

1. 以后每次“自查”先写清检查问题，不再只给结果数字。
2. 任何“通过”都必须注明：通过的是数据、代码、页面，还是语言可读性；不得用一个通过覆盖其他维度。
3. 用户指出“读不懂”时，先回到原句做直译，不以更长的解释掩盖问题。
4. 对外界面不出现具体研究资料的姓名或编号；内部研究依据留在知识库私有资料中。
5. 每次内容结构改变、二次修改和验证结果，都同步写入项目与知识库 Markdown 复盘档。
